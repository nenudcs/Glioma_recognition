================================================================================
任务二运行命令汇总（赛道四 · Goal2：拼接影像 + 重复影像）
================================================================================
适用代码（管线仓库内的插件包，无需改管线其它文件）：
    tasks/goal2_stitched/     拼接检测（规则式，产出 IsStitchedProb）
    tasks/goal2_duplicate/    重复检测（近似重复检索，产出 duplicate_pairs.jsonl）
接线入口：tasks/real_pipeline.py（Goal1 + Goal2 + 其余 Dummy）

服务器路径示例（按你的实际路径替换）：
    仓库根            /2026aicompetition/workspace/dcs/Glioma_recognition
    训练数据根        /2026aicompetition/datasets/training
    测试集（平台给）  /data/testset
    checkpoint 根     /2026aicompetition/workspace/checkpoint
    标定/离线产物     /2026aicompetition/workspace/Glioma_task12_runs
    比赛输出          /2026aicompetition/workspace/answer/<evaluation_id>/
    运行日志          /2026aicompetition/workspace/logs/

三条铁律：
  1) 所有 `python -m tasks.*` 命令都在【仓库根目录】执行；
  2) `tasks/real_pipeline.py` 是插件接线表，被所有真实插件共用 —— 更新代码时
     Goal2 的内容必须“最后覆盖”（顺序 goal1 → goal2），否则会静默绑到 Dummy
     （现象：服务能起，但 IsStitchedProb 恒为 0、重复对只有占位行）；
  3) 标定结果写到 checkpoint 规范路径，服务启动时自动读取；
     环境变量是【临时覆盖】，两者同时存在时以环境变量为准。

首次上手顺序：第 1 节 → 第 2 节 → 第 3 节 → 第 4 节 → 第 5 节 → 第 6 节

“不起服务”的完整流程（与任务一「权重迁移 → 测试 → 离线打分」三步对应）：
    第 1 节 环境 → 第 2 节 接线校验 → 第 3/4 节 标定 → 第 5 节 离线自检
    需要一键跑完时：
        bash tasks/goal2_stitched/verify.sh  --data-root <训练集> --checkpoint-root <ckpt> \
             --out-dir <产物> --workers 8 --skip-service
        bash tasks/goal2_duplicate/verify.sh --data-root <训练集> --checkpoint-root <ckpt> \
             --out-dir <产物> --workers 8 --skip-service
    （第 6 节的服务启动与 mock 只在要上线/演示时再跑）

3. 拼接标定（正类 = annotation/Composition，负类 = 正常影像）
--------------------------------------------------------------------------------

3.1 目录体检（几秒，确认找得到正负类）

python -m tasks.goal2_stitched.dataset --data-root "$DATA_ROOT"
# 输出里 positives>0、negatives>0 才算正常；找不到时用 --annotation-root 指定

3.2 标定阈值（结果自动写到 $CHECKPOINT_ROOT/goal2_stitched/calibration.json）

python -m tasks.goal2_stitched.evaluate \
  --data-root "$DATA_ROOT" \
  --out-dir   "$RUN_DIR" \
  --checkpoint-root "$CHECKPOINT_ROOT" \
  --target-fpr 0.05 --workers 8

# 想几分钟先看个口径：  加 --max-volumes 500（只抽样负类）
# 效果不好换口径再标：  --metric local --stat p99 --band 0.2
# 只打印不落盘：        加 --no-write-calibration

产物：
  $RUN_DIR/stitched_calibration.json            （阈值 + 召回/误报 + AP/ROC-AUC/Recall@10%FPR）
  $CHECKPOINT_ROOT/goal2_stitched/calibration.json   ← 服务启动时读取的那份

7. 环境变量速查
--------------------------------------------------------------------------------

路径类
  GOAL2_CHECKPOINT_ROOT        标定文件根目录（默认 $COMPETITION_WORKSPACE/checkpoint）
  CHECKPOINT_ROOT              goal1/goal2 共用的兜底根目录名
  GOAL2_DATA_ROOT              verify.sh 里的默认训练集根（可选）
  GOAL2_RUN_DIR                verify.sh 里的默认产物目录（可选）

任务二 · 拼接（前缀 GOAL2_STITCHED_）
  GOAL2_STITCHED               1/0 是否启用拼接检测（默认 1）
  GOAL2_STITCHED_THRESHOLD     判定阈值（标定前是占位 0.16，分数=阈值时概率 0.5）
  GOAL2_STITCHED_METRIC        curvature（默认）| adjacent | local
  GOAL2_STITCHED_STAT          max（默认）| p99 | mean
  GOAL2_STITCHED_BAND          层方向两端丢弃比例，默认 0.1
  GOAL2_STITCHED_SCALE         概率映射斜率，默认 8.0
  GOAL2_STITCHED_GATE          命中后是否对下游上闸，默认 1

任务二 · 重复（前缀 GOAL2_DUPLICATE_）
  GOAL2_DUPLICATE              1/0 是否启用重复检测（默认 1）
  GOAL2_DUPLICATE_MODE         near（默认，近似重复）| exact（只认逐像素一致）
  GOAL2_DUPLICATE_SCAN         1 = 先扫全库建索引（默认）；0 = 只与已见过的检查增量比对
  GOAL2_DUPLICATE_SCAN_MAX_VOLUMES  全库扫描条数上限（0 = 不限，可用于限时）
  GOAL2_DUPLICATE_SCAN_WORKERS 全库扫描并行读盘线程数，默认 4
  GOAL2_DUPLICATE_SIM_CENTER   相似度→概率中心，默认 0.90（必须用第 4 节标定）
  GOAL2_DUPLICATE_SIM_SCALE    概率映射斜率，默认 0.02
  GOAL2_DUPLICATE_MIN_SIM      精排相似度下限，默认 0.50（低于不上报）
  GOAL2_DUPLICATE_COARSE_FLOOR 粗检索余弦下限，默认 0.80（低于不精排）
  GOAL2_DUPLICATE_TOP_K        每个检查最多上报的候选对数，默认 20
  GOAL2_DUPLICATE_GATE_PROB    概率达到该值才判定为重复，默认 0.5
  GOAL2_DUPLICATE_GATE         命中后是否对下游上闸，默认 1
  GOAL2_DUPLICATE_REPORT_MIN_PROB 低于该概率不写进提交文件，默认 0.0
  GOAL2_DUPLICATE_MAX_PAIRS    每例最多提交的候选对数，默认 200（赛方稀疏性约束）
  GOAL2_DUPLICATE_SLICES / _COARSE_GRID / _FINE_GRID / _SHIFT   描述子几何，默认 3/12/64/1

闸门
  GOAL2_GATED_FIELDS           被闸门拦下的任务，默认 goal3,goal4,goal5
                               置空（export GOAL2_GATED_FIELDS=）= 完全不上闸

9. 常见报错处置
--------------------------------------------------------------------------------

  契约测试报 “DummyStitchedTask is not Goal2StitchedTask”
      -> tasks/real_pipeline.py 是旧版接线表（被 goal1 覆盖）。按第 2.2 节更新接线表，
         再跑第 2.1 节四条；症状与修法详见 tasks/goal2_stitched/APPLY_NOTES.md

  服务起来了但 IsStitchedProb 恒为 0、duplicate_pairs.jsonl 只有占位行
      -> 同上：绑到了 Dummy。跑第 2.1-c 看任务链名字即可确认

  标定结果没生效（阈值和 calibration.json 不一致）
      -> 之前 export 过 GOAL2_STITCHED_THRESHOLD / GOAL2_DUPLICATE_SIM_CENTER，
         环境变量优先；unset 这两个变量后重启服务

  positives: 0 / gold_pairs: 0
      -> 不是“目录不存在”，而是“成功读入并打分的影像数 = 0”：
         ls "$DATA_ROOT/annotation/Composition" | head
         ls "$DATA_ROOT/annotation/duplicate" | head
         目录名或层级不同就用 --annotation-root 指定

  首次 /call 很久才开始出结果
      -> 重复检测第一次会先扫全库建索引（每个体数据只读中间 3 层）。
         加 TASK2 侧加速：export GOAL2_DUPLICATE_SCAN_WORKERS=8
         想跳过全库扫描：export GOAL2_DUPLICATE_SCAN=0（改成增量比对，召回会下降）

  扫描太慢 / 想先跑通链路
      -> export GOAL2_DUPLICATE_SCAN_MAX_VOLUMES=500 临时限流，正式评测务必改回 0

  下游字段（goal3/4/5）变成中性值
      -> 命中拼接/重复被闸门拦下了。查看 diagnosis：
         python -c "import json;d=json.load(open('<answer>/<检查号>/prediction.json'));print(d)"
         不想上闸：export GOAL2_GATED_FIELDS=

  内存/耗时担心
      -> 描述子约 0.5 KB（粗）+ 12 KB（精，float16）/卷；单对精排约 2 ms；
         全库扫描是主要成本，用 GOAL2_DUPLICATE_SCAN_WORKERS 并行读盘

--------------------------------------------------------------------------------
10. 口径速查（评审对齐）
--------------------------------------------------------------------------------

  拼接：检查级 Partial AUC-PR（Recall≥ 某门限）。分数 = 各序列、各层「当前层 vs
        上下层均值」的最大无量纲差异；阈值必须用 annotation/Composition 标定。
  重复：图像对级 AUC-PR / Recall@10%FPR / Precision@15%Recall。正类 = 金标准对，
        未提交的对按 PairProb=0 计；每例最多 Top-200，按置信度降序。
        赛方定义是「原图轻微调整的复制影像」，因此用近似重复检索而不是逐像素哈希。
  闸门：赛方按金标准筛临床诊断对象，模型预测不参与筛选；误判上闸会让下游字段变中性，
        在意临床分就把 GOAL2_GATED_FIELDS 置空。
